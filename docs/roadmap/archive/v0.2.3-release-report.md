## Qualification, publication, and installation

The exact clean source commit passed the complete `make dist` gate through
Gaori. The gate included `make test`, all-target linting, bounded fuzzing,
release builds, isolated packaged conformance, Dolgorae handoff generation, and
final bundle verification. An earlier candidate run correctly stopped at the
clean-tree package boundary after bounded fuzzing refreshed `fuzz/Cargo.lock`;
the lockfile was committed and the complete gate was rerun from the beginning.
The installed v0.2.2 production daemon remained live throughout qualification.

The annotated tag and `main` were pushed atomically. Exactly four draft assets
were downloaded by numeric asset ID and matched the qualified local bytes before
publication. After publication made the release immutable, the public assets
were downloaded by the same IDs and independently passed final bundle
verification again.

The public archive replaced both installed binaries. One standard
`podway --json daemon install --daemon-path /Users/draccoon/.local/bin/podwayd`
invocation, without a socket override or manual launchctl operation, replaced
the v0.2.2 LaunchAgent successfully. The installed v0.2.3 daemon was then loaded
and reachable as PID `82250`, with the published source, build, and contract
identities. Reading the owning workspace status also succeeded without
`WORKSPACE_STATE_UNREADABLE`.

## Remaining limitations

- The release supports native Apple Silicon macOS only.
- The binaries are unsigned and notarization was not attempted.
- The daemon is a per-user LaunchAgent and starts after GUI login.
- Podway remains a same-user local tool rather than a multi-user security boundary.
- No MCP server or MCP transport is included.
