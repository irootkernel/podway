## Qualification and publication

The exact clean source commit passed `make dist`, including formatting, all-target
Clippy with warnings denied, unit/integration/E2E tests, contract sentinels,
100,000 iterations for each pinned fuzz target, release-profile compilation,
packaged conformance, handoff generation, and final bundle verification.

Packaged conformance passed these scenarios:

- `aut_t_id_custom_procedure_survives_restart_and_completes_the_fenced_lifecycle`;
- `aut_t_id_and_recon_reject_conflicts_and_recover_an_admitted_timeout`; and
- `aut_t_recon_response_loss_is_reconciled_by_lookup_and_exact_replay`.

Repository release immutability was enabled before the draft was created. Every
draft asset digest matched the local qualified bytes, every draft asset was
downloaded by asset ID and passed `tools/verify_release_bundle.py verify`, and the
release was then published. The published release reports `immutable=true`; all
four assets were downloaded by asset ID again and passed the same independent
verification.

The released v0.1.0 and v0.1.1 public v1 schema bytes remain compatible with
v0.1.2. Consumers pinned to the pre-v0.1.0 schema-only snapshot must replace
`list.max_items: 0` with a value in `1..=1000`; released consumers require no
migration.

The v0.1.1 annotated tag, source commit, release ID `363845461`, asset IDs, and
asset digests were rechecked after publication and remained unchanged.

The release commands completed successfully in this order:

```text
make dist
git tag -a v0.1.2 -m "Podway v0.1.2" da461a9ec1746fa435f3d7974e4d27a73a2f8ac7
git push --atomic origin main refs/tags/v0.1.2
gh api --method PUT repos/irootkernel/podway/immutable-releases
gh release create v0.1.2 --verify-tag --draft --title "Podway v0.1.2" --notes-file RELEASE_NOTES.md
gh release upload v0.1.2 <archive> <checksum> <provenance> <handoff>
python3 tools/verify_release_bundle.py verify --output-dir /tmp/podway-draft.PzrOiP
gh release edit v0.1.2 --draft=false
python3 tools/verify_release_bundle.py verify --output-dir /tmp/podway-published.qtUOI8
```

## Remaining limitations

- The release supports native Apple Silicon macOS only.
- The binaries are unsigned and notarization was not attempted.
- The daemon is a per-user LaunchAgent and starts after GUI login.
