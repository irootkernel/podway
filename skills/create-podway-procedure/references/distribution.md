# Distributed Procedure and Group Sources

Read for source shipped to other worktrees or maintained as installed copies.

## Bind support and ownership

Keep one consumer-owned canonical base, separately versioned group definitions,
and byte-identical managed copies. Check with the exact binary that admits
Procedure v3 and Execution Group v1 and reports Output v4, version-result v2 and
contract-manifest v2. Record build/source and manifest identity. For distributed
released support, select an immutable published release that admits every used
feature and validate with that exact binary. Do not establish support with
semver alone. A development candidate establishes only matching source/build
behavior. Both presentation selectors use the same admitted Procedure and Store.

Existing sessions retain their original source and writer identities. Procedure
v2 sessions are settled with the original writer and its matching guidance.
The v16 writer declares no predecessor and refuses legacy Stores.
Do not repoint an existing runtime or replace installed skills or managed files
from a source-only task. A separate consumer adoption owns distribution changes.

## Qualify accepted paths

Prepare a stable accepted-path inventory bound to both canonical digests and the
exact CLI. Include a clean start/begin/design, group activation via the unchanged
interface, scoped evidence, group terminal return and base finish. Cover negative
and conditional gates, local correction, valid guarded replan and replacement,
prior-work dispositions, stale requests and authorized history reads when those
paths belong to the delivered graph. Include goal and delegation settlement
only when declared. Preserve concrete failure premises and current evidence.
Test intentional fault injection only in isolated fixtures.

Run paths through the public CLI in owned Git fixtures. Obtain separate runtime authorization
and follow `$use-podway`. Use changed interface/digest, stale scope
or unmet-guard negative controls as applicable. Verify that rejection leaves
state unchanged and retains no success outcome. Validate complete bounded paging only
when needed by the declared data. Source checks and graph inspection alone
cannot establish runtime or external-adapter behavior.

## Deliver

1. Verify the exact canonical base and groups with the validating binary. Record
   their preview digests plus source SHA-256s if copied byte-for-byte.
2. Hand off the exact preview start suggestion and accepted-path inventory.
   Supply each group source and canonical digest for activation. A separately
   authorized runtime operator supplies the current plan, basis and predecessor
   or prior-work facts.
3. Apply managed copies only within consumer-approved paths after separate
   authorization. Keep configuration and installation policy owned by that
   consumer. Verify copy digests and update applicable consumer pins and guides.
4. Report source validation, isolated runtime proof, published-release support,
   existing-session compatibility and installed adoption separately.

Ship reviewed static source. Do not generate a distributed graph dynamically
during setup or execute start or activation as part of authoring.
